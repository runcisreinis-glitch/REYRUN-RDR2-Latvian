# REYRUNでゲームをラトビア語に翻訳する

![REYRUN](https://reyrun-rdr2-latviski.runcisreinis.chatgpt.site/assets/reyrun.png)

Red Dead Redemption 2をラトビア語で遊ぶ方は、[プロジェクトのサイト](https://reyrun-rdr2-latviski.runcisreinis.chatgpt.site/ja/)から翻訳と導入手順を入手できます。別のゲームを翻訳・校正する場合は、`reyrun-game-translation-lv`フォルダーを丸ごとコピーしてください。手順、練習用の5例、手元で使う検査ツールが入っています。

最初の練習が終わったら、[より複雑なテキストの確認方法](https://reyrun-rdr2-latviski.runcisreinis.chatgpt.site/ja/method/techniques/)を試してください。[RDR2プロジェクトの記録](https://reyrun-rdr2-latviski.runcisreinis.chatgpt.site/ja/method/retrospective/)では、過去の下訳をどう回収し、校正済みの文章がどの段階で止まっていたかをどう調べたかを、実際の件数とともに紹介しています。

## 自分で始める場合とAIに頼む場合

チャットに`SKILL.md`、この手順、少量の原文を添付します。フォルダーからスキルを読み込めるアシスタントなら、**フォルダー全体**を指定の場所にコピーし、一覧を更新して`reyrun-game-translation-lv`を選びます。手順やスクリプトへの相対リンクが使えるよう、ファイルの配置はそのままにします。JSONLを自分で編集し、Pythonで検査することもできます。特定のAIサービスや有料アカウントは必要ありません。

最初の練習では`examples/source.jsonl`を添付し、次のように依頼してください。

> SKILL.mdを読んで、5件の原文をすべてラトビア語に訳してください。入力項目はすべてそのまま残し、target、decision、reasonを加えてください。意味が確定できない行はholdにして、何が分かれば判断できるか書いてください。前置きや後書きを付けず、1行に1件のJSONオブジェクトを返してください。ゲームへ入れる前に私が確認します。

回答をUTF-8の`my-edits.jsonl`として保存し、判断を`examples/edited.jsonl`と照合します。自然な訳は一つとは限りません。証人のせりふを声に出し、求められる動作とボタンのコードが合っているか、文脈不足でどの行が保留になったかを確かめます。

## ゲームのテキスト5件で試す

スキルのフォルダーで端末を開きます。Python 3.8以降が必要です。Windows環境によっては`python`の代わりに`py -3`を使います。

    python scripts/localization_tools.py prepare examples/source.jsonl --output demo-packets --max-rows 2
    python scripts/localization_tools.py validate --inputs examples/source.jsonl --edited examples/edited.jsonl --report demo-qa.json
    python -B -m unittest discover -s scripts -p "test_*.py"

最初のコマンドは5件を2件、2件、1件に分けます。次のコマンドでは原文IDが5件、readyが4件、holdが1件と表示されます。得点欄は変数と区切り記号だけなので、原文と同じだという警告は想定どおりです。`my-edits.jsonl`でも報告ファイル名を変えて試してください。使い捨てのコピーで**訳文だけから**`~INPUT_INTERACT~`を消すと、該当行を示して終了コード2を返します。以前の結果を残すため、実行ごとに別の出力先を使います。

## 自分のゲームから原文を用意する

対象ゲーム用のツールで原文を書き出し、元ファイル、ビルド番号、リソース名、ゲーム内部のキーを保存します。一度に扱うのは同じビルドでIDが重複しない範囲です。別のリソースで同じIDを使う場合は別々に検査します。入力はUTF-8のJSON配列か、1行1オブジェクトのJSONLです。原文のハッシュは、デコード後の文字列全体を末尾に改行を加えずUTF-8にしたバイト列のSHA-256です。Pythonでは`hashlib.sha256(source.encode("utf-8")).hexdigest()`と書きます。

| 項目                                                        | 入力する内容                                                                                                                         |
|-------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------|
| `id`, `native_id`                                           | 作業用の一意で固定のIDと、分かる場合はゲーム内部のキーを書きます。言語パックの版が変わると行の並びが変わることがあります。           |
| `source`, `source_sha`                                      | コード、空白、改行を含む原文全体とそのチェックサムです。                                                                             |
| `candidate`                                                 | 既存の下訳を記入します。なければ空文字列を使います。                                                                                 |
| `context`, `context_id`, `speaker`, `scene_id`, `branch_id` | 話者、場面、プレイヤーに見える内容のうち確認できたものを記入します。不明な項目は省きます。IDの並びだけでは会話の順番は決まりません。 |
| `target`, `decision`, `reason`                              | ラトビア語の訳、判断、必要に応じて質問や根拠を、編集用コピーにだけ加えます。                                                         |

担当者ごとに異なるIDを割り当てます。人名、地名、用語は全員が同じ承認版を使い、格変化を含む用例を添えます。登場人物どうしが敬称から親しい言い方へ変わる場合は、その場面を記録します。

## せりふの意味と話し方を確かめる

以下は練習用の例文です。RDR2の引用ではありません。

| 原文と場面                                                                          | ラトビア語訳                                             | 校正で確かめる点                                                                                                         |
|-------------------------------------------------------------------------------------|----------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------|
| ポーズ画面の “Resume”                                                               | **Turpināt**                                             | ボタン内に収まる短い動作名です。                                                                                         |
| “Hold `~INPUT_INTERACT~` to open the gate.”                                         | **Turi nospiestu ~INPUT_INTERACT~, lai atvērtu vārtus.** | ボタンは長押しします。一度押すだけでは別の操作になります。                                                               |
| “I... I didn't take it.” と言う、動揺した証人                                       | **Es… Es to nepaņēmu.**                                  | ためらいと否定を両方残し、せりふ全体を声に出します。                                                                     |
| “Can you wait here?” 子どもが友達に頼む場合と、店員が見知らぬ相手に丁寧に頼む場合。 | **Vari te pagaidīt?** / **Vai jūs varētu te pagaidīt?**  | 二人の関係によって呼びかけ方が変わります。                                                                               |
| 個数が変わるアイテム欄の “Charges: {count}”                                         | **Lādiņu skaits: {count}**                               | 文字列が一つだけなら、どの数にも合う表示を使います。複数形を個別に扱えるゲームでは、各形式を訳し、対応する数で試します。 |
| 場面もアイテムの種類も不明な “Seal”                                                 | **hold**                                                 | アザラシ、印章、それとも「封じる」という指示でしょうか。リソースや画像を調べてから訳語を決めます。                       |

承認前に原文と訳文を二度読みます。最初は誰が誰に何をしたか、否定や条件が結果をどう変えるかを確かめます。次は人物らしい話し方、語形、字幕の長さ、画面に収まるかを確認します。辞書で語形は調べられますが、意味の選択には場面が必要です。承認した訳は校正記録と一緒に保存し、書き換えたら読み直します。

## ゲームファイルを確認し、再開に備えて記録する

検査ツールは原文のハッシュ、IDの重複・欠落、既知の文脈項目、readyなのに空の訳文を検出します。チルダで囲んだRDRコードとその順序、波括弧の単純な引数、代表的なprintf書式も照合します。番号付き引数は並べ替えられますが、番号がなければ型の並びを保ちます。同じ`%s`が二つあっても意味は入れ替わり得るため、値の位置を人が確認します。改行数の変化は警告になります。入れ子のICUメッセージ、HTML、フォント指定や独自コードには専用の検査を加えます。

`tm-index`と`tm-suggest`は承認済みの訳を候補として返します。照合キーにはゲーム、言語、原文ハッシュ、文脈IDと、文脈・校正規則・用語集の各版を含めます。校正記録への参照、承認訳と記録ファイルのハッシュを登録します。相対パスを使う場合は両方のコマンドを同じ作業フォルダーで実行します。同じキーに異なる承認訳があれば競合一覧に出ます。コマンド一覧は`python scripts/localization_tools.py --help`で確認できます。

スキルのフォルダーで次の2コマンドを実行します。同梱の校正記録はポーズ画面の「Turpināt」に対応し、同じ文脈版では候補が1件返ります。

    python scripts/localization_tools.py tm-index examples/tm-approved.jsonl --output demo-tm.json
    python scripts/localization_tools.py tm-suggest examples/tm-query.jsonl --index demo-tm.json --output demo-suggestions.json

対象ゲーム用のツールでリリースを作り、技術上の例外と未解決の行は別々に記録します。旧ファイルはゲームフォルダー外に保存します。一人の担当者がビルドとの一致を確かめ、承認版を書き込みます。RDR2のStringTable XMLなら、以下のパスを実際のものに置き換えてください。数値キーとデコードした文字列を*表全体*で照合し、両ファイルのハッシュを表示します。順序やXML表記が違えば、キーと本文が同じでもバイト単位のハッシュは変わります。

    python scripts/compare_xml.py "reviewed/Latvian Translation.xml" "installed/Latvian Translation.xml"

対象モードでメニュー、表示時間の短い字幕、長いアイテム名、複数の値を取る変数を確認します。**ā, č, ē, ģ, ī, ķ, ļ, ņ, š, ū, ž**の表示も見ます。不具合報告にはビルド、分かればID、原文、現在の訳、場面、画像を添えます。元に戻せるよう前の承認版を手元に残します。

各バッチの最後に、直近で導入したファイルのハッシュ、承認したテキストの版、保留中のIDを記録します。同じ時間帯について、新規導入IDと原文の表示文字数を数えます。下訳、校正、書き出し、待機時間は別々に記録します。再開時は最新記録と実際のゲームファイルを照合してから次を割り当てます。
